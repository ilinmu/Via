# Via UI 设计与交互规范

## 1. 设计目标

Via 的设置面板采用跟随系统的简约风格。界面优先保证可读性和低门槛，不用装饰性背景或多种强调色争夺注意力。

核心原则：

- 使用系统语义颜色，自动适配浅色和深色外观，不硬编码深色块。
- 系统蓝是唯一强调色；橙色和红色只表达警告和错误。
- 图标使用单色 SF Symbols，不叠加发光、渐变或固定信号色。
- 功能按“状态 / 网络 / 设置”三个 Tab 分区；首次使用时用三步向导引导。
- 状态 Tab 只展示用户做判断所需的语义状态，不直接展示 CoreWLAN 接口名或原始英文运行日志。
- 业务文案支持简体中文和英文。

## 2. 设计令牌

| 令牌 | 取值 |
| --- | --- |
| 面板背景 | `Color(nsColor: .windowBackgroundColor)` |
| 输入框背景 | `Color(nsColor: .textBackgroundColor)` |
| 分隔线 | `Divider()` / `Color(nsColor: .separatorColor)` |
| 主文字 | `.primary` |
| 次文字 | `.secondary` / `.tertiary` |
| 强调 | `Color.accentColor`（系统蓝） |
| 警告 / 错误 | `.orange` / `.red`（仅语义状态） |
| 成功 | `.green`（仅状态徽标） |
| 间距 | 4 / 8 / 10 / 12 / 16 / 20；摘要行上下统一 10 |
| 圆角 | 输入框 8，面板 12（连续圆角） |
| 字体 | `.title3`、`.headline`、`.body`、`.subheadline`、`.caption` 等语义样式 |

令牌定义在 `Sources/Via/DesignSystem/PanelLayout.swift`，不要在新视图中直接写十六进制颜色或自定义阴影。

## 3. 面板结构

面板固定宽度 400 点，高度随内容测量，最低 360 点，最高取状态栏所在屏幕可见高度减 24 点，且不超过 680 点。内容超过可用高度时在根滚动区域内滚动。

菜单栏图标左键打开或关闭面板；右键或 Control-点击显示系统菜单，菜单项为本地化的“退出应用”，不会打开面板。

顶部固定区域：

1. 小号 `wifi` 图标、应用标题。
2. Tab 模式：下方三分段 Tab 栏承担全部导航；标题栏右侧不重复放置设置入口。
3. 向导模式：右上角 `1 / 3` 进度文本；第 1、2 步提供“跳过”文字按钮。向导不显示 Tab 栏。
4. Tab 模式下按需显示提醒横幅：定位权限未就绪、网络设置未完成。

Tab 模式的内容区域：

| Tab | 内容 |
| --- | --- |
| 状态 | 当前连接、自动切换开关、下次检查、未保存提示、P/B 摘要、扫描和刷新 |
| 网络 | P/B 的 SSID 与密码编辑、扫描、保存 |
| 设置 | 登录时启动、语言、使用说明、重新运行向导、检查间隔、关于、退出 |

## 4. 状态 Tab

1. `ConnectionSummary`：当前网络名（`.title3`）、本地化网络角色、运行状态徽标。徽标高度与左侧 40 点 Wi-Fi 图标一致，文字使用 `.body`，始终带文字，颜色只表达语义：
   - 运行中：绿色；
   - 等待定位权限：橙色；
   - 正在开启：系统蓝 + 旋转指示；
   - 已暂停：次级灰色。
2. 自动切换：`Toggle` + 一行说明。
   - 未运行时，只有配置完整且定位权限为“始终”才可开启。
   - 运行中始终允许关闭，即使权限后来被撤销。
   - `isStarting` 期间禁用并显示 `ProgressView`，防止重复点击。
3. 下次检查：运行时使用 `TimelineView` 每秒更新倒计时；启动检查期间显示“正在检查”；权限未就绪时显示“等待定位权限”。
4. 未保存提示：草稿有改动时显示橙色提示和“去设置”，点击切到网络 Tab。
5. P/B 摘要：两行只读摘要，右侧显示 SSID 或“未设置”，点击切到网络 Tab。
6. 操作：`扫描网络`（共享扫描状态）和 `刷新状态`。
7. 异常：自动切换已开启但权限不是“始终”时，状态徽标显示“等待定位权限”，顶部横幅提供系统设置入口。

状态页不提供“立即检查”或“手动连接”，不新增业务入口。

## 5. 网络 Tab

1. 标题和一句说明：优先使用 P，P 不可用时切换到 B。
2. `NetworkSetupForm`：扫描行、权限提示、P/B 两个网络编辑器。每个编辑器包含 SSID 输入、可滚动的扫描建议列表（展示全部结果）、密码输入和显示/隐藏按钮。
3. 定位权限被拒绝时扫描按钮禁用并显示说明；手动输入 SSID 仍可用。
4. 凭据写入警告以 `WarningBanner` 显示。
5. 底部保存行：未保存/已保存状态、`保存更改` 按钮，以及“保存后生效；密码保存在本机钥匙串中”的小字说明。

编辑采用草稿 + 显式保存：

- 输入先写入 `NetworkDraft`，点击“保存更改”才提交到 `AppState`。
- 校验两个 SSID 去空白后非空，且不区分大小写不相同；密码可留空。
- 保存按钮在有改动时始终可点击，无效输入点击后显示校验错误，而不是静默禁用。
- 切换 Tab 不会丢失草稿，扫描结果也不会重置。

## 6. 设置 Tab

1. 通用：
   - 登录时启动 `Toggle`；系统要求批准时禁用，并显示警告横幅和“打开登录项设置”。
   - 语言：下拉选择器，便于后续增加更多语言。
   - 使用说明：内联 `DisclosureGroup`，展开后显示可选择的 `help_content`。
   - `重新运行设置向导`文字按钮。
2. 自动切换：
   - 检查间隔输入框 + “秒”，回车或失焦时提交，经 `AppState` 归一化到 5–3600。
   - 下方显示范围提示。
3. 关于：
   - 版本号（版本 + 构建号）。
   - 仅本机处理的隐私说明。
   - 红色“退出应用”文字按钮。

## 7. 首次向导

配置不完整（P 或 B 去空白为空）时，`PanelModel` 在初始化时进入向导。路由只在初始化时决定一次，编辑过程中清空 SSID 不会再次触发向导。向导分三步：

1. **授权定位**：解释 macOS 为什么把 Wi-Fi 名称视为位置信息。已授权显示“已授权”；未决定显示“授权定位”；被拒绝或仅“使用期间”显示“打开系统设置”和“需要允许‘始终’访问”的提示。未授权也允许继续，但提示只能手动输入 SSID。
2. **选择网络**：复用 `NetworkSetupForm`。两个 SSID 有效后才能“下一步”；密码可留空。
3. **完成**：显示 P、B 和定位权限摘要。主按钮“开启自动切换”仅在配置有效且权限为“始终”时可用；次按钮“仅保存”始终可用（配置有效时）。完成后进入 Tab 模式并停在状态 Tab。

跳过：

- 第 1、2 步可跳过，进入 Tab 模式并选中网络 Tab，保留草稿。
- 顶部显示“网络设置尚未完成 / 继续设置”横幅，可回到向导；已授权时从选择网络开始，否则从授权开始。

向导只根据配置完整性判断，不新增持久化标志。配置完整后下次启动自然不再出现。

## 8. 无障碍与本地化

- Tab 栏、自动切换开关、语言选择器和密码字段都设置 `accessibilityLabel`。
- 状态徽标始终同时提供文字，不只依赖颜色。
- 按钮和输入框使用系统控件与语义字号，支持系统“增大文字”和键盘导航。
- 密码字段保留原生编辑快捷键（Command-X/C/V/A）和右键菜单，并在明文/密文切换时同步无障碍标签。
- 跟随语言切换的内容包括 Tab 名称、状态、网络配置、权限提示、向导步骤、设置项和帮助正文。
- 缺失本地化 Key 时会直接显示 Key 本身；新增文案必须同步补齐中英文。

## 9. 面板高度与滚动

`SettingsView` 用两个 `PreferenceKey` 分别测量固定顶部区域（`chromeHeight`）和滚动内容（`contentHeight`）：

```swift
totalHeight = max(
    min(chromeHeight + min(contentHeight, metrics.maxHeight - chromeHeight), metrics.maxHeight),
    PanelLayout.minHeight
)
```

- 只测量内容，不测量 `ScrollView` 本身，避免布局循环。
- `PanelMetrics.maxHeight` 由 `AppDelegate` 根据状态栏所在屏幕计算，并在打开面板和屏幕参数变化时更新。
- `main.swift` 的窗口高度更新和首次拟合高度再做一次上限钳制。
- 不做窗口高度动画，避免切换 Tab 时抖动。
- 向导底部按钮位于滚动内容末尾，小屏上可滚动到达。
